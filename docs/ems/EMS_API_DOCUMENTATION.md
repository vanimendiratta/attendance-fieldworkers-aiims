# EMS API Specification

## 1. Authentication & Common Headers

All EMS endpoints are mounted under `/api/ems/` and require authorization via HTTP Bearer token. The server transparently supports:
1. **Attendance Session Tokens**: Generated by parent application login (`/api/login`, `/api/admin/login`).
2. **EMS Native JWTs**: Generated by EMS login (`/api/ems/auth/login`).

```http
Authorization: Bearer <session_or_jwt_token>
Content-Type: application/json
```

## 2. Employee Endpoints

### 2.1 Get Leave Balances
- **Endpoint**: `GET /api/ems/leave/balances`
- **Description**: Returns the real-time balance for the authenticated employee across all leave types.
- **Access**: Employee, Administrator.
- **Response `200 OK`**:
```json
{
  "success": true,
  "data": [
    {
      "leave_type": "CL",
      "allocated": 8.0,
      "used": 2.0,
      "pending": 0.0,
      "balance": 6.0
    },
    {
      "leave_type": "EL",
      "allocated": 30.0,
      "used": 5.0,
      "pending": 0.0,
      "balance": 25.0
    },
    {
      "leave_type": "RH",
      "allocated": 2.0,
      "used": 1.0,
```

### 2.2 Calculate Leave Working Days Preview
- **Endpoint**: `POST /api/ems/leave/calculate`
- **Description**: Evaluates dates against calendar, weekly-off schedule, and gazetted holidays before submission.
- **Request Body**:
```json
{
  "leave_type": "CL",
  "start_date": "2026-10-19",
  "end_date": "2026-10-21",
  "is_half_day": false,
  "half_day_period": null
}
```
- **Response `200 OK`**:
```json
{
  "success": true,
  "data": {
    "calendar_days": 3,
    "deductible_days": 2,
    "holiday_count": 1,
    "weekend_count": 0,
    "holidays": [
      {
        "date": "2026-10-20",
        "name": "Dussehra (Vijay Dashami)"
      }
    ],
    "message": "Calculation successful: 2 working days deductible (1 holiday excluded)."
  }
}
```

---

### 2.3 Submit Leave Application
- **Endpoint**: `POST /api/ems/leave/apply`
- **Description**: Validates balance, checks date overlaps, reserves days via ledger debit, and creates request in `PENDING` status.
- **Request Body**:
```json
{
  "leave_type": "CL",
  "start_date": "2026-10-19",
  "end_date": "2026-10-21",
  "is_half_day": false,
  "half_day_period": null,
  "reason": "Family obligation in hometown"
}
```
- **Response `201 Created`**:
```json
{
  "success": true,
  "data": {
    "request_id": 1042,
    "employee_id": 4,
    "leave_type": "CL",
    "days_requested": 2,
    "status": "PENDING",
    "created_at": "2026-10-21T10:00:00.000Z"
  }
}
```
- **Error Responses**:
  - `400 Bad Request`: `{"success": false, "error": "Insufficient CL balance. Available: 1.0, Required: 2.0"}`
  - `400 Bad Request`: `{"success": false, "error": "Selected dates overlap with an existing leave request (#1021)"}`

### 2.4 List Personal Leave Requests
- **Endpoint**: `GET /api/ems/leave/requests`
- **Description**: Lists all historical and active leave requests for the calling employee.
- **Response `200 OK`**:
```json
{
  "success": true,
  "data": [
    {
      "id": 1042,
      "leave_type": "CL",
      "start_date": "2026-10-19",
      "end_date": "2026-10-21",
      "days_requested": 2,
      "status": "PENDING",
      "reason": "Family obligation in hometown",
      "admin_remarks": null,
      "created_at": "2026-10-21T10:00:00.000Z"
    }
  ]
}
```

---

### 2.5 Cancel Leave Request
- **Endpoint**: `POST /api/ems/leave/cancel/:id`
- **Description**: Allows an employee to cancel an unapproved or future approved request, automatically restoring deducted leave balances.
- **Response `200 OK`**:
```json
{
  "success": true,
  "message": "Leave request #1042 cancelled successfully. Balances restored."
}
```

## 3. Administrative Endpoints

### 3.1 List Pending Leave Approvals
- **Endpoint**: `GET /api/ems/admin/leave/pending`
- **Description**: Fetches all pending leave applications across the organization or restricted by admin jurisdiction.
- **Access**: Administrator (`admin`, `super_admin`).
- **Response `200 OK`**:
```json
{
  "success": true,
  "data": [
    {
      "id": 1042,
      "employee_id": 4,
      "employee_name": "Aakash Verma",
      "employee_code": "FW-004",
      "designation": "Field Investigator",
      "leave_type": "CL",
      "start_date": "2026-10-19",
      "end_date": "2026-10-21",
      "days_requested": 2,
      "reason": "Family obligation in hometown",
      "status": "PENDING",
      "submitted_at": "2026-10-21T10:00:00.000Z"
    }
  ]
}
```

---

### 3.2 Review Leave Request (Approve / Reject / Hold)
- **Endpoint**: `POST /api/ems/admin/leave/review`
- **Access**: Administrator.
- **Request Body**:
```json
{
  "request_id": 1042,
  "action": "APPROVE",
  "remarks": "Approved. Ensure coverage for assigned village survey."
}
```
*(Actions supported: `APPROVE`, `REJECT`, `HOLD`)*
- **Response `200 OK`**:
```json
{
  "success": true,
  "message": "Leave request #1042 successfully updated to APPROVED."
}
```

---

### 3.3 Staff Leave Register
- **Endpoint**: `GET /api/ems/admin/leave/requests`
- **Parameters**: `status`, `leave_type`, `employee_id`, `start_date`, `end_date`.
- **Response `200 OK`**: Array of all leave requests matching query filters.

---

### 3.4 Manual Balance Adjustment
- **Endpoint**: `POST /api/ems/admin/adjust-balance`
- **Access**: Super Admin / System Admin.
- **Request Body**:
```json
{
  "employee_id": 4,
  "leave_type": "CL",
  "adjustment_type": "CREDIT",
  "days": 1.0,
  "reason": "Discretionary compensatory adjustment for special health camp duty"
}
```
- **Response `200 OK`**:
```json
{
  "success": true,
  "message": "Adjusted CL balance for employee #4 (+1.0 days)."
}
```

